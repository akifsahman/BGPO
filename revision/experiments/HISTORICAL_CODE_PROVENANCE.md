# Historical code provenance

The executable notebook in `historical/notebook/pool_ablation_notebook.ipynb` imports `benchmark_pipeline_pool_ablation.py`, reports 44 KEEL datasets, and writes `benchmark_results_pool_ablation.xlsx` and `benchmark_summary_pool_ablation.xlsx`. The script and notebook are byte-identical to their counterparts under `Pool-Select/` (SHA-256 for the script: `c35a0f47e95c4e011d48202c0b3e56a1e9af5b49561f9b5ffed2c25922f47f8f`).

The old submitted manuscript's Table 3 values match `Pool-Select/benchmark_results_pool_ablation.xlsx`, sheet `Classifier Mean Results`, rate 1.0, `Pool_SMOTE_ADASYN_MWMOTE_G_SMOTE`. For example, SVM BND F1 is 0.5689 (workbook 0.568913), KNN BND G-Mean is 0.8337 (workbook 0.833709), and RF BND F1 is 0.6987 (workbook 0.698669). Thus this notebook pipeline is the numerical provenance of at least those published table entries.

The original submitted manuscript's Eq. 9--13 and Supplementary Algorithm 4 specify mean distances to separate minority and majority neighborhoods and selection of the highest-scoring `N_new` candidates. `historical/notebook/benchmark_pipeline_pool_ablation.py` instead computes a class-proportion score in the ten nearest *combined* training observations (`1 - abs(p_min - p_maj)`) and samples candidate indices randomly with probability proportional to the shifted score. The discrepancy is methodological, not just a naming or folder difference.

The separate `the earlier independent BGPO package` package **does** implement the manuscript's distance score and deterministic top-budget selection. On Pima fold 1, abalone19 fold 1, and iris0 fold 5, its selected candidate coordinates and order exactly matched the corrected reference implementation under the same training-only transformed inputs; as recorded in the original development audit. These three checks do not prove parity on every fold, but they establish that the corrected benchmark is testing the manuscript-style method rather than the notebook's different stochastic method.

Consequently the historical table can be attributed to the notebook pipeline, while the manuscript's stated algorithm is represented by the package and corrected reference code. Both codebases exist; a claim that the historical numeric results validate the manuscript's distance/top-budget rule would require a new computation using that rule.
